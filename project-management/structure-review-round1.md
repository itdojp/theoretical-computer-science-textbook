# 1. 書籍の概要

- 想定読者（`docs/index.md` / `src/introduction/*` の記述ベース）
  - 理論計算機科学を体系的に学びたい大学生・大学院生・研究者、および理論背景を押さえたいエンジニア。
  - 抽象的な定義・定理・証明を扱うため、初学者でも「数学的記法の読み慣れ」は一定程度必要（不足は導入章で補う想定）。
- 本書で達成しようとしているゴール（`docs/index.md` の記述ベース）
  - 計算理論・形式言語・オートマトン・複雑性理論・アルゴリズム解析などの主要トピックを整理し、相互関係を説明できるようにする。
  - 定義や定理を例・証明スケッチと結びつけ、直感と形式の対応を作る。
  - 研究や高度な設計議論で必要となる理論的な基礎体力を養う。

## 3. 構成上の気になる点（候補）

- 見出しレベルの一貫性（`#` の混在）
  - 本文中に `# ...` の見出しが複数登場し、章のトップ見出しと同じレベルになっている箇所がある（例: 第1章/第2章/第3章/第5章）。目次や読書の区切りとして誤認される可能性がある。
- 「まとめ」「章末問題」の配置（第1章）
  - 第1章で「まとめ」「章末問題」が章中盤に出現し、その後に 1.1.3 が続く構成になっている。読者が「章を読み終えた」と誤認しやすい。
- 想定読者の幅が広い
  - `docs/index.md` では大学生〜研究者までを対象としており、読者の初期条件が広い。導入のガイドはあるが、章ごとの「最低限ライン（ここまで理解すればOK）」が章末に明示されると自習しやすい。

## 4. 構成改善の提案（案）

- 見出しレベルの正規化（ToCの安定化）
  - 章内の補助的な見出しは `##` / `###` に揃え、`#` を章タイトルに限定する（必要なら見出しではなくコードブロック/引用/太字にする）。
- 第1章の「まとめ」「章末問題」を章末へ移動する
  - 章内の節（1.1.3 以降）を完結させたうえで、最後にまとめ・問題を配置する。
- 章末に「到達点チェック（最低限/標準/発展）」を追加する
  - 読者の目的に応じた学習深度を選べるよう、章末に「最低限ここまで」「標準」「発展」を分けたチェックリストを置く（内容は既存の学習目標・章末問題を再整理するだけでも効果がある）。
